This ledger records the owner-operable CLI surface used to build, supervise, inspect, recover, and remove projects without the desktop UI. It distinguishes live qualification from inventory-only coverage and does not treat generated checks as acceptance evidence.

## Acceptance rules

- Product checks generated by an agent are evidence, not proof; independent requirement inspection is mandatory.
- A terminal receipt passes only when every effective retry leaf is successful, integration-ready, and durably delivered to Chat.
- Failed retry ancestors remain visible for provenance but do not override a successful authoritative leaf.
- Parallel work requires server-validated disjoint scopes and one aggregate final review.
- Ordinary progress never wakes the Coordinator. Questions/blockers may wake it once; clean work uses at most one planning and one final-review turn.
- Worktree-local checks cannot be represented as post-integration aggregate evidence.
- No generated fixture, managed worktree, isolated database, token, or backup is retained after final qualification.

## Known bounded limitations

- A broad `cargo test --workspace --all-targets` compilation reached Windows linker/PDB and disk limits before executing tests. No assertion failed. Final qualification therefore uses single-job, no-debug-info package suites plus desktop and packaging gates, and records the broad invocation as environmental—not green.
- GitHub authenticated mutation remains owner-connection gated.
- Linux and macOS package qualification require their native hosts and are outside this Windows portable gate.
